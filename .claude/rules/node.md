# Node rules (loaded when a .ts file under src or tests, or a migration, is touched)

- Zod at every boundary: every route declares `schema` through the type
  provider; `process.env` is read only in `src/config.ts`; types are
  `z.infer`, never a duplicate interface. No `any`, `!` or silencing `as`.
- A route parses, calls one service, replies. No SQL, no business rule, no
  error body in a route; services throw `AppError` subclasses and
  `src/errors.ts` maps them once.
- Every promise is awaited or returned; `void promise` only with a comment
  saying why. Every outbound call has a timeout and an `AbortSignal`.
- Repositories own SQL through Drizzle and return typed rows; services own
  transactions; every list query is bounded and ordered; no `sql.raw` with
  interpolated values.
- Log through `request.log` or `app.log` (pino, request id bound); never a
  token, password, cookie or body; never `console.log`.
- Migrations come from `drizzle-kit generate`, are read line by line, keep
  `drizzle/meta` untouched, and are applied by a release step, not on boot.
- Shutdown: SIGTERM closes the server, ends the pool, flushes traces;
  `process.exit` only in `src/server.ts`.
- Tests: `app.inject` for routes, `buildApp` per test with injected deps,
  no real database in `src/**/*.test.ts`, no `setTimeout` waits, no network.
  A bug fix ships with its test.
- `pnpm-lock.yaml` is committed and regenerated by `pnpm install`, never
  edited. No `eslint-disable` without a task id and a reason on the line.
