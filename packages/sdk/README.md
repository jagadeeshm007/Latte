# @latte/sdk

A small TypeScript client for the Latte API (ADR-0019, ADR-0027). It has no
dependencies: about 16 kB of plain JavaScript using `fetch` and Web Crypto, so it runs
on Node 20 or later, Bun, Deno, Cloudflare Workers and other edge runtimes. Types for
every request and response ship with it. The full guide is in the app under
Developers > Docs, and in [docs/api/guide.md](../../docs/api/guide.md).

## Install

Each release is a tarball on GitHub; no registry or token is needed.

```bash
npm install https://github.com/jagadeeshm007/Latte/releases/download/sdk-v0.2.0/latte-sdk-0.2.0.tgz
```

The same URL works with `pnpm add` and `yarn add`, and is what lands in your
`package.json`, so the version stays pinned. For whatever is newest, use
`https://github.com/jagadeeshm007/Latte/releases/latest/download/latte-sdk.tgz`.

## Use

```ts
import { LatteClient } from "@latte/sdk";

const latte = new LatteClient({
  apiKey: process.env.LATTE_API_KEY!,
  baseUrl: "https://latte.example.com",
});

// Upload a batch in chunks; failed files come back in `failed`, the rest carry on.
const batch = await latte.batches.create(files, {
  name: "Inbound, 16 Oct",
  onProgress: console.log,
});
const done = await latte.batches.wait(batch.batchId!);
const csv = await latte.batches.resultsCsv(done.id);
```

Create a key under Developers in the app, with only the scopes the integration needs.

## Methods

| Namespace   | Methods                                                                             | Scope                                                                 |
| ----------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| (client)    | `me()`, `reference()`                                                               | none for `me()`, `calls:read` for `reference()`                       |
| `calls`     | `list`, `get`, `audioUrl`, `upload`, `retry`, `archive`, `unarchive`                | `calls:read`, `calls:write`                                           |
| `batches`   | `list`, `get`, `create`, `wait`, `update`, `retryFailed`, `resultsCsv`, `exportZip` | `batches:read`, `batches:write`; `exports:read` for the two downloads |
| `analytics` | `dashboard`, `highlights`, `leaderboard`                                            | `analytics:read`                                                      |
| `webhooks`  | `list`, `get`, `create`, `update`, `delete`, `test`, `deliveries`, `redeliver`      | `webhooks:write`                                                      |

## Transcripts without audio

```ts
import { parseTranscript } from "@latte/sdk";

// One call from labelled text (or pass lines: [{ speaker, text, startMs?, endMs? }]).
await latte.calls.uploadTranscript({
  originalFilename: "call-0042.txt",
  agentId,
  teamId,
  productId,
  callDate: "2026-10-22",
  text: "Agent: Good morning, this is Ravi.\nCustomer: Hi.",
});

// Many, as one batch in chunks; names other than Agent/Customer via speakers.
await latte.batches.createFromTranscripts(transcripts, { name: "Dialler export" });

parseTranscript("[00:00] Agent: Hello.\n[00:04] Customer: Hi."); // lines with times
```

Text takes one turn per line, `Agent:` or `Customer:` (also Rep, Advisor, Client, Caller), with an optional time like `[00:41]`; a line without a label continues the turn above. JSON takes a list of lines, or `{ "lines": [...] }`. `parseTranscript` throws `TranscriptParseError` naming the line it could not read.

## Behaviour

- **Retries.** A 429 is retried after `Retry-After` (three times by default, `maxRetries`). Server errors and dropped connections are retried on reads always, and on writes only when the write carries an idempotency key.
- **Idempotency.** Writes take `{ idempotencyKey }`. The same key replays the first response for 24 hours; the same key with a different body is refused with 422. `calls.upload` sets one for you from the file's storage path.
- **Types, not run-time checks.** Responses are typed from the API's own schemas (generated by `scripts/gen-types.ts`, checked in CI), and are not validated at run time, which keeps the SDK small.
- **Errors.** Errors are `ApiError` (or `RateLimitError`) with the server's `code` and `requestId`. Quote the request id when asking for help.
- **Personal data.** Transcripts and quotes come back with card numbers, phone numbers, Aadhaar, PAN, IFSC, account numbers and email addresses masked. `callDetail.redactions` says how many spans were masked. Keys never receive the unmasked text.

## Webhooks

Check every delivery before trusting it. Pass the raw body, not parsed JSON:

```ts
import { verifyWebhookSignature } from "@latte/sdk";

app.post("/latte", express.text({ type: "application/json" }), async (req, res) => {
  const ok = await verifyWebhookSignature({
    secret: process.env.LATTE_WEBHOOK_SECRET!,
    header: req.header("Latte-Signature"),
    body: req.body,
  });
  if (!ok) return res.status(400).end();
  const event = JSON.parse(req.body);
  // event.type is call.scored, call.failed, batch.completed, alert.triggered or digest.ready
  res.status(204).end();
});
```

`verifyWebhookSignature` returns a promise, because Web Crypto is asynchronous.
Deliveries older than five minutes fail the check (`toleranceSeconds`). Use the
`Latte-Delivery` header to drop a redelivery you have already handled.

## Working on the SDK

- `pnpm --filter @latte/sdk gen:types` after a schema change in `packages/shared`; `make typecheck` fails until you do.
- `make sdk-pack` builds `dist/` (failing above a 20 kB budget) and packs `latte-sdk-<version>.tgz`.
- To release: bump `version` in `package.json` (and the URLs in this README and the in-app docs), then push the tag `sdk-v<version>`. The `sdk-release` workflow attaches the tarball to a GitHub release.
